# ⚖️ Біржа хламу

Симулятор аукціону/біржі в стилі MMO: гравці та боти виставляють і купують ресурси, крафтять,
демпінгують і перенасичують ринок.

## Запуск

```bash
uv sync
uv run uvicorn trader.main:app --port 8077
# http://localhost:8077
```

Під час першого запуску створюється `data/trader.db`, і рушій «прокручує» ~6 ігрових днів історії,
щоб графіки не були порожніми. Щоб почати світ із нуля, видаліть `data/trader.db*`.

## Як це влаштовано

| Модуль | Що робить |
|---|---|
| `trader/catalog.py` | 151 товар (сировина, хлам, напівфабрикати, готові речі), 110 рецептів, NPC-споживачі, шаблони подій |
| `trader/seed.py` | базові ціни крафтових речей рахуються з дерева рецептів; створює ~70 ботів |
| `trader/market.py` | книга ордерів: ескроу, матчинг за ціною й часом, комісія біржі, депозит, NPC-торговець, крафт |
| `trader/engine.py` | симуляція: тік = 10 ігрових хвилин, свічка = 30 хв |
| `trader/workers.py` | найм: ринок праці, контракти, ЗП, харчування, інструменти, рівні, черги крафту |
| `trader/gw2.py` | опційна синхронізація настроїв із Guild Wars 2 Trading Post |
| `trader/api.py` | REST API |
| `web/` | клієнт (vanilla JS + Chart.js) |

**Боти:** збирачі (видобувають сировину), ремісники (крафтять, коли це вигідно, і виставляють заявки
на інгредієнти), NPC-споживачі (таверна, армія, двір… — купують нижче своєї оцінки й «споживають» товар),
перекупники (скуповують дешеві лоти), новачки (зливають лут за безцінь або NPC-торговцю).

**Щоб ринок був схожий на людей, а не на скрипт:**
- боти грають сесіями (зайшов → поторгував → вийшов), ввечері онлайн більший, ніж уранці;
- у продавців різні стилі: «підрізальник», «ставлю поруч з найдешевшим», «знаю собі ціну»;
- перед виставленням продавець оцінює, чи лот продасться до кінця терміну (черга дешевших лотів
  та швидкість продажів); на мертвому ринку товар здебільшого притримують, а не демпінгують;
- переставляють лоти переважно одразу після входу в гру і лише там, де товар реально купують;
- непроданий лот вчить: наступного разу цей продавець ставить дешевше;
- попит NPC приходить по кожному товару випадковим потоком: популярність товару × дрейф × події × час доби.

**Події:** війни, патчі з бафом/нерфом дропу, ботоферми, бан-хвилі, картелі. Вони створюють
дефіцит і перенасичення.

## Найм працівників (вкладка 👷)

Сировину гравець не «збирає кнопкою», а наймає людей. Кожен працівник має професію, рівень (Новачок → Легенда),
риси (працьовитий, лінивий, пияк, сова, ненажера, ощадливий…), настрій і досвід.

- **Ринок праці**: 14 кандидатів, оновлюється кожні 6 год гри. Кандидат чекає 0.5–2 доби.
- **Ліцензія гільдії** обмежує кількість працівників: 2 → 4 → 6 → 9 → 12 місць.
- **Контракт**: 1/3/7/14 днів; довший контракт дешевший за день (×1.1 … ×0.85). Перший день оплачується одразу,
  далі ЗП списується щодня. Два несплачені дні — працівник іде. Звільнення коштує неустойку в один день ЗП.
- **Харчування −20% ЗП**: працівник щодня їсть із вашого інвентаря (пайки, пироги, рагу, хліб, яйця…).
  Різноманітна їжа піднімає настрій. Без їжі він голодний і працює вполсили. Пиякам потрібне пиво.
- **Інструмент −15% ЗП**: ви обіцяєте видати інструмент (сокиру, кирку, ліхтар…). Інструмент дає бонус до виробітку
  і зношується ~8% за день. Якщо обіцянку не виконати, настрій падає.
- **Збирачі** видобувають сировину своєї професії. Рідкісні знахідки доступні лише досвідченим.
  Можна задати фокус на конкретний ресурс. «Збирач хламу» дешевий, але приносить переважно мотлох.
- **Ремісники** знають рецепти свого рівня і мають спеціалізацію (+30% швидкості). Їм задають чергу до 3 рецептів
  із лімітом запасу («тримати 20 руків'їв»), і вони крафтять, поки є інгредієнти.
- З досвідом працівник підвищує рівень, але при продовженні контракту просить більшу ЗП.

Так будуються логістичні ланцюги: фермер → кухар (їжа для всіх) → лісоруб і шахтар → коваль (сокири й кирки для них)…

## Умови ринку (вкладка ⚙️)

Параметри задаються наживо або пресетами для навчання: звичайний, спокійний, волатильний,
низька/висока комісія, перенасичення, дефіцит, криза.

- **% біржі** — комісія з продажу (типово 5%)
- депозит за лот, глобальний попит і видобуток, волатильність, частота подій, активність ботів, швидкість часу

## Тюнінг симуляції

```bash
uv run python scripts/simulate.py --days 6 --verbose
uv run python scripts/simulate.py --days 6 --preset oversupply --set ah_cut_pct=10
uv run python scripts/undercut_test.py   # як швидко боти підрізають лот гравця
uv run python scripts/workers_test.py    # окупність найманих працівників
```

Звіт `simulate.py` показує: скільки товарів «мертві» (без угод), наскільки ціни відхилилися від базових,
чи є перенасичення, і як ціна й кількість лотів реагували на кожну подію.
